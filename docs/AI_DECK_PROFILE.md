# AI 덱 설정 양식

자동 모드 AI 상대(`SimulatorAIDeck`)를 만들고 다듬기 위한 안내서입니다.
관리자 화면 **배틀로그 › AI 덱**에서 덱을 고르고 **AI 설정(TOML)** 칸을 채우면,
로비의 "AI와 대전"에 그 AI가 나타납니다.

- 양식 원본: [`LumenGG/battlelog/game/ai_profile_template.toml`](../LumenGG/battlelog/game/ai_profile_template.toml) (새 AI 덱을 만들면 이 내용이 기본으로 채워집니다)
- 해석·검증 코드: `battlelog/game/ai_profile.py`
- 배틀 예측(대처 카드·패배 확정): `battlelog/game/ai_preview.py`
- 선택 알고리즘: `battlelog/game/ai.py`
- 테스트: `battlelog/test_ai_deck.py`

저장할 때 TOML 문법과 카드 코드(덱에 있는 카드인지)를 검사하고, 저장한 뒤에는
**해석 결과** 칸에서 AI가 실제로 읽은 내용을 확인할 수 있습니다. 설정이 틀린 AI는
로비에 나오지 않습니다. 대전을 시작하면 그 시점의 설정이 세션에 고정되므로,
설정을 고쳐도 이미 진행 중인 대전에는 영향이 없습니다.

## 1. AI가 카드를 고르는 순서

매 순간 AI는 지금 할 수 있는 행동(레디, 획득, 콤보, 캐치, 페이즈 종료 등) 각각에
점수를 매기고 다음 순서로 하나를 고릅니다.

1. **패배 확정 카드 제외**: 레디 후보 중 [4절](#4-패배-확정-카드-피하기-safety)의 조건에 걸리는 카드는 뺍니다.
   단, 모든 레디 후보가 걸리면 아무것도 빼지 않습니다.
2. **점수 계산**: 각 행동의 점수는 아래 항목을 모두 더한 값입니다.
   - 정책 점수: `Σ 가중치 × 특징값`. 가중치는 공통 정책 → 성향 프리셋 → `[weights]` → 조건이 맞는 `[[situation]]`의 `weights` 순서로 덮어씁니다.
   - 선호 점수: `[prefer]`와 조건이 맞는 `[[situation]]`의 `prefer`에서, 행동에 들어간 카드 코드의 점수를 더합니다.
   - 콤보 루트 점수: [3절](#3-콤보-루트-combo)
   - 대처 점수: [5절](#5-상대-카드-대처-counter)
   - 패 구성 점수(획득만): [5절 끝](#겟-페이즈-패-구성-hand)
3. **후보 추리기와 가중 랜덤**: 1등 행동이 카드를 내는 행동이면, 1등과 점수 차가 2.5 이내인
   카드 행동 중 상위 3개를 후보로 남기고 `exp((점수 - 1등 점수) / 0.75)` 비율로 하나를 뽑습니다.
   페이즈 종료·타이머 같은 진행 버튼은 항상 1등을 고릅니다.
   단, 겟 페이즈에서 패가 가득 찼고 어떤 교체도 패를 `hand.swap_margin`만큼 낫게 하지 못하면
   1등이 획득이어도 넘깁니다.

AI는 상대가 볼 수 있는 정보만 씁니다. 상대 손패는 모두 한 번 이상 공개되므로(시작 패 확인, 공개 획득)
AI는 상대 손패 전체를 기억합니다(엔진 `observe(include_memory=True)`의 `memory.rival_hand`).
상대가 뒷면으로 레디한 뒤에는 무엇을 냈는지 모르고, 레디 전 손패 중 하나라는 것만 압니다
(`memory.rival_ready_pool`, 섞어서 코드 순으로 정렬). 사람 화면에는 바뀌는 것이 없습니다.

### 레디: 행렬 게임

레디는 `ai_matrix.py`가 행렬 게임으로 고릅니다.

1. 행 = 내 레디 후보, 열 = 상대가 낼 수 있는 카드(손패 또는 레디 후보 묶음).
2. 칸 = 그 둘이 붙었을 때 나에게 좋은 정도.
   - **수치표 평가**(`ai_outcomes.py`, 실제 대전 AI 기본값): 아래 「수치표」 참고. 판정은 카드 수치로
     계산하고, 판정 뒤 결과(콤보 데미지, 카운터, 카드 이득, FP)는 카드별로 미리 잰 평균값을 씁니다.
     효과가 판정을 자주 바꾸는 카드가 낀 칸만 엔진 평가로 다시 계산합니다.
   - **엔진 평가**(`ai_engine_eval.py`): 엔진을 복사해 두 카드를 실제로 레디시키고
     배틀(캐치·콤보·효과 선택 포함)을 끝까지 진행해 본 결과입니다. (준 데미지 - 받은 데미지) / 400
     + FP 차이 / 6, 게임을 이기면 +20. 카드 효과·패시브·지속 효과가 모두 반영됩니다.
     상대가 이미 뒷면으로 레디했다면, 열마다 그 자리에 후보 카드를 넣어 계산합니다.
   - **기본 수치 예측**(엔진이 없을 때): 속도·위치·방어/회피/상쇄·FP만 본 `battle_value`.
     데미지를 주면 +1, 받으면 -1, FP 차이 1당 1/6, 콤보 판정이면 +0.5.
3. 덱 설정의 선호 카드·콤보 루트·상황별 선호는 행마다 더해집니다(점수 ÷ 6). 즉 "이 카드를 내라"가
   아니라 그 카드의 가치를 올리는 방식이라, 덱 전체가 계속 후보로 남습니다.
4. 서로 최선을 다할 때의 혼합 전략(내쉬 균형)을 구해 그 확률대로 뽑습니다. 상대가 읽기 어렵고,
   수비를 뚫는 카드가 적은 상대에게는 수비 비중이 저절로 올라갑니다.

상대 손패를 모르면(기억이 없는 관측) 예전처럼 선형 점수 + 상위 3장 가중 랜덤으로 고릅니다.
자기 대전 훈련은 선형 가중치를 맞추는 것이라 레디도 선형 점수로 고릅니다(`ready_strategy='policy'`).

| Django 설정 | 기본값 | 뜻 |
|---|---|---|
| `LUMEN_AI_READY_EVAL` | `table` | `table` 수치표, `engine` 모든 칸 엔진 평가(레디 한 번에 몇 초), `base` 기본 수치 예측 |
| `LUMEN_AI_TABLE_ENGINE_CELLS` | `False` | `True`면 수치표에서 판정이 자주 바뀌는 카드의 칸만 엔진 평가(레디당 약 1초 추가) |
| `LUMEN_AI_ENGINE_READY_EVAL` | `True` | `False`면 엔진 평가를 전혀 쓰지 않음(`engine` 모드는 기본 수치 예측으로) |

루트 덱 대 11개 캐릭터 6판씩(상대는 기존 정책 AI) 측정: 수치표 41승 25패(레디당 약 6ms),
수치표 + 엔진 칸 41승 25패(약 1.1초), 엔진 평가 36승 30패(약 3~4초), 기본 수치 예측 35승 31패.
이어서 차지 규칙에 속도 우위 조건을 넣은 뒤 수치표 54승 11패(레브 0-6 → 4-2, 리타 0-6 → 4-2).

서버가 바쁘면(대기 결정이 작업 프로세스 수 × `LUMEN_AI_SHED_QUEUE`를 넘으면) 엔진 칸 없이 계산합니다.

### 수치표 (`ai_outcome_table.json`)

사람이 레디를 고를 때처럼 계산을 줄입니다.

1. **판정**: 두 카드의 속도·위치·방어/회피/상쇄·FP로 히트/카운터/가드 등을 정합니다.
   사용 시·판정 전에 속도를 바꾸는 효과(예: 루트 차지 상태의 "2속도 느려짐")는 카드에 인쇄되지 않으므로,
   자기대전에서 잰 실제 최종 속도와 인쇄 속도의 차이를 **카드 × 그 플레이어의 켜진 상태**별로 저장해
   보정합니다. 그 카드의 표본이 없으면 같은 상태의 전체 평균을 씁니다.
2. **판정 뒤 결과**: 카드 코드 × 판정 결과마다, 그 카드 주인이 그 배틀에서 얻은 평균 자원을 표에서 찾습니다.

   | 자원 | 뜻 |
   |---|---|
   | `damage` | 준 데미지(콤보·추가 데미지 포함) |
   | `fp` | 배틀이 끝났을 때 내 FP(다음 배틀 속도) |
   | `counter` | 늘어난 패시브 카운터 수 |
   | `card` | 늘어난 손패 수(레디한 카드 1장은 빼고 셈. 콤보로 쓰면 줄어듦) |

3. **칸 값** = (내 자원 - 상대 자원)을 가치로 바꾼 합. 데미지 400 = 1(배틀 한 번), FP 6 = 1,
   카운터 1개 = HP 200, 카드 1장 = HP 300. 이 데미지로 상대 HP가 0이 되면 +20.
4. **열 정리**: 다른 카드보다 모든 경우에 상대에게 나쁜 카드(예: 프레임 이득이 적을 때의 느린 기술,
   같은 카드 두 장)는 상대가 낼 이유가 없으므로 열에서 뺍니다. 균형 전략의 값은 바뀌지 않습니다.
5. **엔진 칸**(`LUMEN_AI_TABLE_ENGINE_CELLS`를 켰을 때): 자기대전에서 카드 수치 예측과 실제 판정이 20% 넘게 달랐던 카드(속도 변경, 판정 변경,
   방어 무시 같은 효과)가 낀 칸만 엔진 평가로 계산합니다. 그런 상대 카드의 열은 정리하지 않습니다.

표에 없거나 표본이 3번보다 적은 칸은 카드에 인쇄된 데미지·FP와 섞어 씁니다. 콤보 판정인데 표에
없는 카드는 같은 캐릭터 콤보 카드들의 평균 추가 데미지를 더합니다.

**표 만들기** (DB는 읽기만 하고 JSON 파일만 씁니다. 먼저 `--dry-run`으로 확인):

```powershell
cd LumenGG; ..\.venv\Scripts\python.exe manage.py build_ai_outcome_table --deck 9 --deck 10 --games 3 --dry-run
```

`--deck`을 빼면 활성 AI 덱 전부로 서로 대전합니다. 카드 효과가 바뀌는 릴리스 뒤에는 다시 만듭니다.

**덱 설정에서 고치기**: 캐릭터마다 정립된 수치가 있으면 표보다 우선합니다. 상대 카드도 적을 수 있습니다.

```toml
[outcome."ST2-AT-001".hit]          # 이 카드가 히트하면
damage = 2000                       # 콤보까지 약 2000
counter = 3                         # 카운터 3개

[outcome."AWL-AT-031".guarded]      # 상대 카드가 가드당하면 (상대 기준 값)
fp = -4

[resources]                         # 자원 1단위를 HP 몇으로 볼지
counter = 300                       # 이 캐릭터는 카운터가 중요
card = 300
fp = 67
```

판정 결과 이름: `hit` 히트, `counter` 카운터 히트, `clash` 상쇄, `countered` 카운터 당함,
`dodge` 회피, `opponent_dodge` 상대가 회피, `guard` 가드함, `guarded` 가드당함,
`failed_defense` 수비 실패, `none` 둘 다 수비.

## 2. 양식 항목

```toml
style = "balanced"          # 성향 프리셋

[weights]                   # 공통 가중치 덮어쓰기 (항상)
card_attack = 2.0

[prefer]                    # 항상 적용되는 선호 카드: "코드" = 점수(-10~10)
"UNC-AT-001" = 2.5

[[situation]]               # 상황별 선호 (여러 개 가능)
name = "체력이 낮을 때는 수비"
when = { my_hp_max = 1500, action = ["ready"] }
prefer = { "UNC-DF-003" = 3 }
weights = { card_defense = 2.0 }

[[combo]]                   # 콤보 루트 (여러 개 가능)
name = "기본 루트"
cards = ["UNC-AT-001", "UNC-AT-002", "UNC-AT-003"]
bonus = 3
when = { rival_hp_min = 1501 }

[counter]                   # 상대 카드 대처
enabled = true
bonus = 2.0
scope = "hand"

[hand]                      # 겟 페이즈 패 구성
enabled = true
bonus = 8.0
keep = 3
swap_margin = 0.1

[safety]                    # 안전장치
avoid_certain_loss = true
```

`#` 뒤는 메모입니다. 왜 그 값을 넣었는지 옆에 적어 두면 나중에 고치기 쉽습니다.

### 성향 프리셋 (`style`)

공통 정책 가중치 위에 아래 값을 덮어씁니다. 그 위에 `[weights]`가 다시 덮어씁니다.

| 값 | 이름 | 덮어쓰는 가중치 |
|---|---|---|
| `balanced` | 균형 | 없음 |
| `aggressive` | 공격적 | card_attack 2.5, card_defense -0.5, card_damage 0.45, hp_advantage_attack 0.8 |
| `defensive` | 수비적 | card_attack 0.6, card_defense 1.5, low_hp_defense 2.5 |
| `speed` | 속도 중시 | card_speed 1.6, card_damage 0.1 |

### 가중치 표 (`[weights]`, `situation.weights`)

점수 = 가중치 × 특징값. 특징값은 카드를 내는 행동에만 붙고, 행동 종류 키는 그 행동이면 1입니다.
"기본값"은 코드에 들어 있는 기본 정책 값이며, 실제 대전은 활성 AI 정책 값을 씁니다
(관리자 화면 AI 덱의 **참고표 › 가중치 표**에서 현재 값을 볼 수 있습니다).
가중치 범위는 -20~20입니다. 기권·되감기·일시정지 가중치는 바꿀 수 없습니다.

| 키 | 기본값 | 뜻 |
|---|---|---|
| `card_damage` | 0.213 | 카드 데미지 100당 점수 |
| `card_speed` | 1.106 | 속도 1 빠를수록(12 - 속도) 점수 |
| `card_attack` | 1.093 | 공격 카드면 더하는 점수 |
| `card_defense` | 0.211 | 수비 카드면 더하는 점수 |
| `zero_damage_attack` | -12 | 데미지 0 공격 카드면 더하는 점수(보통 음수) |
| `low_hp_defense` | 1.005 | 내 체력 1500 이하에서 수비 카드면 더하는 점수 |
| `hp_advantage_attack` | 0.318 | 공격 카드일 때 (내 체력 - 상대 체력)/5000 에 곱하는 점수 |
| `ready_card` | 1.253 | 레디 행동 자체의 기본 점수 |
| `select_get_card` | 1.574 | 리스트 카드 획득 행동의 기본 점수 |
| `select_ultimate` | 2.141 | 얼티밋 획득 행동의 기본 점수 |
| `play_combo_card` | 1.599 | 콤보 카드 1장 사용의 기본 점수 |
| `play_combo_pair` | 1.620 | 콤보 첫 2장 사용의 기본 점수 |
| `select_combo_first` | 1.620 | 콤보 첫 장 고르기의 기본 점수 |
| `select_combo_followup` | 1.630 | 콤보 두 번째 장 고르기의 기본 점수 |
| `end_combo` | -0.386 | 콤보를 끝내는 행동의 점수(높을수록 일찍 끝냄) |
| `play_catch_card` | 1.765 | 캐치 카드 사용의 기본 점수 |
| `decline_catch` | -0.136 | 캐치를 하지 않는 행동의 점수 |
| `pass_phase` | 0.026 | 페이즈를 넘기는 행동의 점수 |
| `submit_decision` | 0.791 | 효과 선택을 확정하는 행동의 점수 |
| `battle_preview` | 6 | 레디 예측(약 -2~+2) × 상대 손패를 아는 비율에 곱하는 점수 |
| `preview_trust` | 0.7 | 상대 손패를 다 알 때 대리 점수(속도·데미지·공수)를 줄이는 비율(0~1) |

점수 감각: 속도가 1 빠른 카드는 약 1.1점, 데미지 100 높은 카드는 약 0.2점 앞섭니다.
1등과 2.5점 넘게 차이 나는 카드는 랜덤 후보에서도 빠지므로, 선호 점수 2~3이면
"비슷하면 이 카드", 5 이상이면 "웬만하면 이 카드"라는 뜻이 됩니다.

### 조건표 (`when`)

`when` 안의 조건은 **모두** 맞아야 합니다. 빠진 조건은 따지지 않습니다.

| 키 | 뜻 |
|---|---|
| `action` | 행동 종류 목록: `ready`(레디) `get`(획득) `combo`(콤보) `catch`(캐치) |
| `turn_min` / `turn_max` | 이 턴 이상 / 이하 |
| `my_hp_min` / `my_hp_max` | 내 체력 이상 / 이하 |
| `rival_hp_min` / `rival_hp_max` | 상대 체력 이상 / 이하 |
| `hp_lead_min` / `hp_lead_max` | (내 체력 - 상대 체력) 이상 / 이하. 음수면 지고 있을 때 |
| `my_fp_min` / `my_fp_max` | 내 FP 이상 / 이하 |
| `fp_lead_min` / `fp_lead_max` | (내 FP - 상대 FP) 이상 / 이하. "+4FP 상황"은 `fp_lead_min = 4`, "-3~-1FP"는 `fp_lead_min = -3, fp_lead_max = -1` |
| `speed_lead_min` / `speed_lead_max` | 속도 우위: 상대의 가장 빠른 공개·기억 공격 속도 - 내 손패의 가장 빠른 공격 속도(FP 반영). 양수면 내가 빠름. 상대 공격을 모르면 99, 내 공격이 없으면 -99 |
| `combo_min` / `combo_max` | 이번 콤보에서 이미 쓴 콤보 카드 수 이상 / 이하 |
| `rival_shows` | 상대의 공개된 카드(배틀·손패·리스트) 중 하나라도 이 코드면 (다른 덱 카드 코드도 가능) |
| `i_hold` | 내 손패에 이 코드 중 하나라도 있으면 |
| `hand_min` / `hand_max` | 내 손패 장수 이상 / 이하 |
| `hand_attack_min` / `hand_attack_max` | 내 손패의 공격 기술 장수 이상 / 이하 |
| `hand_defense_min` / `hand_defense_max` | 내 손패의 수비 기술 장수 이상 / 이하 |
| `my_lumen_min` / `my_lumen_max` | 내 루멘 존 카드 장수 이상 / 이하 |
| `my_counter_min` / `my_counter_max` | 내 패시브 카운터 이상 / 이하. 예: `{ foresight = 2 }`, `{ howling = 5 }` |

예: `when = { hp_lead_max = -1000, action = ["ready", "catch"] }` → 1000 이상 지고 있을 때의 레디·캐치.

## 3. 콤보 루트 (`[[combo]]`)

`cards`는 순서대로 쓸 카드 코드 2~10장입니다. 첫 장은 배틀에서 이긴 레디 카드(콤보의 시작)이거나
첫 콤보 카드입니다. 콤보는 히트·카운터 판정이 "콤보"인 카드로 이겨야 시작되므로, 첫 장을 레디 카드로
쓴다면 그런 카드여야 합니다. 관리자 화면의 "덱 카드 코드" 목록에 `콤보 시작(히트/카운터)`으로 표시됩니다.
루트의 나머지 카드는 그때 손패에 있어야 쓸 수 있으므로, AI는 루트 카드를 획득할 때도 점수를 조금 더 받습니다. 루트는 최대 30개이고, `when`이 있으면 그 상황에서만 씁니다.
상황마다 루트를 나누려면 같은 시작 카드로 `when`이 다른 루트를 여러 개 쓰면 됩니다.

- **콤보 중**: (배틀 카드 + 이미 쓴 콤보 카드 + 고른 첫 장 + 이번에 낼 카드) 순서의 끝부분이
  루트의 앞부분과 같으면, 이번에 낼 카드 1장당 `bonus`를 더합니다. 루트 마지막 장까지 맞으면
  `bonus × 0.5`를 한 번 더 더합니다. 여러 루트가 맞으면 가장 큰 값 하나만 씁니다.
- **레디**: 루트의 첫 장을 레디하면 `bonus × 0.5`.
- **획득**: 루트에 들어 있는 카드를 획득하면 `bonus × 0.3`.

## 4. 패배 확정 카드 피하기 (`[safety]`)

`avoid_certain_loss = true`(기본)이면 레디할 때, **상대가 레디할 수 있는 카드가 모두 공개되어 있고**
그 전부에게 지는 카드는 내지 않습니다. 상대가 이미 뒷면으로 레디했거나 손패에 비공개 카드가
하나라도 있으면 확정이 아니므로 아무것도 빼지 않습니다.

"진다"는 기본 수치로 본 배틀 예측에서 내가 피해를 받고(상대 결과가 히트·카운터) 나는 주지 못하는
경우입니다. 예측은 엔진의 배틀 판정 중 핵심 부분만 따릅니다.

- 공격 대 공격: 회피 키워드 → 같은 최종 속도면 서로 히트 → 느린 쪽의 상쇄 → 최종 속도(속도 - FP)가 빠른 쪽이 카운터
- 공격 대 수비: 공격 위치에 대한 수비 카드의 회피·방어·상쇄, 없으면 히트.
  "상대는 이 기술을 방어할 수 없다"가 조건 없이 적힌 공격(그랩 등)에는 방어가 히트로 바뀝니다(회피·상쇄는 그대로).
  FP·상태 조건이 붙은 방어 불가는 반영하지 않습니다.
- 수비 대 수비: 아무 일도 없음

그 밖의 카드 효과, 지속 효과, 판정 금지 규칙은 반영하지 않습니다. 그래서 이 기능은 "확실히 손해인 카드를 피하는"
보조 장치일 뿐이고, 실제 판정은 항상 엔진이 합니다.

## 5. 상대 카드 대처 (`[counter]`)

획득 단계에서 다음을 계산합니다(`enabled = true`가 기본).

1. 상대의 공개된 카드(`scope = "hand"`: 배틀·손패, `"hand_and_list"`: 리스트까지)를 위협 목록으로 봅니다.
2. 내 손패에 이미 지지 않는 카드가 있는 위협은 뺍니다.
3. 남은 위협을, 지금 획득할 수 있는 리스트 카드 중 **가장 적은 장수**로 모두 막는 조합을 찾습니다
   (3장까지는 모든 조합을 확인하고, 그보다 많으면 많이 막는 카드부터 고릅니다).
4. 가장 작은 조합에 들어가는 카드를 획득하는 행동에 `bonus`(기본 2.0)를 더합니다.
   같은 크기 조합이 여럿이면 모두 가산하고, 그중에서 다시 점수와 랜덤으로 고릅니다.
5. **상대 이득 프레임 대비**: 1~4를 상대가 `guard_fp`(기본 3) FP 앞선 상황(내 FP 0)으로 한 번 더 계산해,
   그때 막을 카드가 손패에 없는 위협(빠른 하단 공격, 방어 불가 공격 등)을 막는 카드에 `guard_bonus`(기본 6.0)를
   더합니다. 지금 FP가 같으면 빠른 공격이 모든 위협을 "막는" 것으로 보이지만, 상대가 이득 프레임이 되면
   공격은 지고 위치가 맞는 가드만 남기 때문입니다. 공격 카드의 기본 점수(속도·공격 가중치)를 넘어야 해서
   일반 대처 가산보다 큽니다. 두 가산이 겹치면 큰 쪽만 더합니다. `guard_bonus = 0`이면 끕니다.

```toml
[counter]
guard_bonus = 6.0   # 상대 이득 프레임 대비 가드 획득 가산(0이면 끔, -10~10)
guard_fp = 3        # 상대가 몇 FP 앞섰다고 볼지(0~20)
```

"막는다"는 4절의 예측에서 그 위협에게 지지 않는다는 뜻입니다.

### 겟 페이즈 패 구성 (`[hand]`)

획득할 카드와 버릴 카드, 넘길지를 패 전체의 가치로 정합니다(`battlelog/game/ai_hand.py`).

- **패 가치** = 대처 + 두께. 상대 카드는 공개된 손패(기억 포함, 가중치 1)와 리스트(가져올 수 있으므로 0.5)입니다.
  - 대처: 상대 카드마다 내 패에서 가장 잘 맞서는 카드의 예측 배틀 값(4절의 기본 능력치 예측, 약 -2~+2)의 가중 평균.
  - 두께: 상대 카드 전체에 대한 평균 배틀 값이 높은 내 카드 `keep`장(기본 3)의 평균. 한 장이 모든 카드에 맞서도,
    상대에게 강한 카드를 몇 장은 쥐고 있게 합니다.
- **획득**: 패가 늘 자리가 있으면 그 카드를 더한 패 가치, 패가 가득 찼으면 더한 뒤 가장 덜 필요한 카드를 돌려놓은
  패 가치로 이득을 계산해 `bonus × 이득`(기본 8.0)을 획득 점수에 더합니다.
- **넘기기**: 패가 가득 차서 넘길 수 있을 때, 가장 큰 이득이 `swap_margin`(기본 0.1)보다 작으면 넘깁니다.
  같은 카드를 가져왔다가 바로 돌려놓는 일이 없어집니다. 상대 카드를 하나도 모르면 가득 찬 패는 그대로 둡니다.
- **버릴 카드**(패 매수 상한 조정): 빼도 패 가치가 가장 덜 떨어지는 카드를 돌려놓습니다. `[[effect]]`에
  `decision = "hand_limit_discard"` 규칙이 있으면 그 규칙이 먼저입니다. 레디할 수 없는 카드(공격·수비가 아닌 카드)는
  이 계산으로 버리지 않습니다.
- 얼티밋 획득은 바꾸지 않습니다. 카드 효과는 반영하지 않으므로, 효과가 중요한 카드는 `[prefer]`나 `[[situation]]`으로 보완합니다.

```toml
[hand]
enabled = true      # false면 예전처럼 정책 점수로만 획득하고, 버릴 카드는 엔진 기본값
bonus = 8.0         # 패 가치 1당 획득 가산(-20~20)
keep = 3            # 두텁게 쥘 카드 수(1~10)
swap_margin = 0.1   # 교체에 필요한 최소 이득(0~4)
```

## 6. 선택형 효과·패시브 (`[[effect]]`)

카드나 패시브가 "~할 수 있다", "~중 하나를 선택", "~장 고른다"처럼 선택을 요구하면,
AI는 아래 순서로 답합니다.

1. AI 덱 설정의 `[[effect]]` 규칙(위에서부터)
2. 모든 AI에 적용되는 캐릭터별 기본 규칙 [`ai_effect_defaults.toml`](../LumenGG/battlelog/game/ai_effect_defaults.toml)(위에서부터)
3. 규칙이 없으면: "할 수 있다"(발동 여부) 효과는 `[effects] default_use`(기본 `true`)대로, 그 밖의 선택은 엔진 기본값

규칙은 **대상**(`ability` 능력 ID, `card` 카드 코드, `decision` 결정 종류 중 하나 이상)과 `when` 조건이
모두 맞을 때 적용됩니다. 항목마다 맞는 첫 규칙이 정하므로, 조건이 좁은 규칙을 위에, 넓은 규칙을 아래에 둡니다.

```toml
[[effect]]
name = "공격이 많을 때만 차지"
ability = "st2-ps1-charge-enter"
when = { hand_attack_min = 2 }
use = true

[[effect]]
name = "그 밖에는 차지하지 않음"
ability = "st2-ps1-charge-enter"
use = false

[[effect]]
name = "리스트에서 가져올 카드"
card = "UNC-AT-001"
decision = "effect_choice"
pick = ["UNC-AT-002", "UNC-AT-003"]
avoid = ["UNC-AT-009"]
count = "max"
```

| 항목 | 뜻 |
|---|---|
| `ability` | 능력 ID(또는 목록). 관리자 화면 참고표의 "기본 패시브 규칙"에 패시브 능력 ID가 있습니다 |
| `card` | 카드 코드(또는 목록). 그 카드의 모든 능력에 적용 |
| `decision` | 결정 종류(또는 목록). 아래 표 |
| `when` | 상황 조건(조건표와 같음) |
| `use` | `true` 발동 / `false` 발동하지 않음. 고르지 않아도 되는 선택이면 `false`는 "아무것도 고르지 않음" |
| `choose` | 효과 분기 ID 우선순위. 고를 수 있는 것 중 앞쪽부터(쿨다운 등으로 빠진 분기는 건너뜀) |
| `pick` | 가져오거나 고를 카드 코드 우선순위. 지정한 카드는 최대 장수 안에서 모두 고름 |
| `avoid` | 되도록 고르지 않을 카드 코드 |
| `count` | 고를 장수: `"max"` `"min"` 또는 숫자 |
| `amount` | 수치 선택: `"max"` `"min"` 또는 숫자(가장 가까운 값) |

| 결정 종류 | 언제 나오나 | 쓰는 항목 |
|---|---|---|
| `optional_effect` | "~할 수 있다" 발동 여부 | `use` |
| `effect_branch` | 여러 효과 중 하나 선택 | `choose`, `use` |
| `effect_choice` | 카드 고르기(가져오기·보내기·배치 등) | `pick`, `avoid`, `count`, `use` |
| `ability_target` | 효과 대상 고르기 | `pick`, `avoid`, `count` |
| `effect_amount` | 수치 고르기 | `amount` |

### 캐릭터별 기본 패시브 규칙

선택이 있는 패시브는 아래 9개이고, 모두 기본 규칙이 있습니다. 카드 텍스트만 보고 정한 첫 기준이므로
실전 기록을 보고 `ai_effect_defaults.toml`이나 덱 설정에서 고쳐 주세요.

| 캐릭터 | 패시브 · 능력 ID | 기본 규칙 |
|---|---|---|
| 루트 | 「차지」 `st2-ps1-charge-enter` | 손패 공격 2장 이상이고, 2속도 느려져도 상대의 가장 빠른 공격보다 빠를 때(`speed_lead_min = 3`)만 사용 |
| 요한 | 서드아이 `crs-ps-002-n1` | 사용, 추가로 제거할 예지 카운터는 최소(0) |
| CMYK | 잼 데이 `dfr-ps-001-n1` | 사용, 둘 수 있는 만큼(최대 3장) 배치 |
| 리타 | 레기온 `lmi-ps-001-bless` | 체력이 1000 이상 밀리거나 손패 수비 2장 이상이면 가디언, 그 밖에는 어쌔신 → 팔라딘 |
| 이제벨 | 피의 잔향 `pmp-ps-001-n2` | 사용(거미 토큰으로 200데미지) |
| 니아 | 「오버 리밋」 `st1-ps1-over-limit-recovery` | 루멘 존 6장 이상이면 냐 기술 브레이크, 아니면 2장 보내기 |
| 울프 | 「위압」 `st5-ps1-intimidation-enter` | 손패 공격 2장 이상이면 사용, 아니면 아낌 |
| 이오몽 | 오목눈이 영물 `cb01-ps-001-n3` | 사용(패 4장 이하일 때 리스트에서 획득) |
| 부쿠키 | 프로스트 베일 `cb04-ps-001-n2` | 사용(서리 부여 시 부쿠키 기술을 루멘 존으로) |

선택이 없는 패시브(레브, 린, 키메라, 미녕이, 무영, 핀프, 델피, 키스, 비올라, 타오)는 엔진이 자동으로 처리합니다.
무영·핀프의 "게임 시작 시 ~장까지 배치할 수 있다"처럼 장수를 고르는 효과는 `effect_choice`로 나오며,
규칙이 없으면 엔진 기본값을 따릅니다. 필요하면 `card`와 `count`로 규칙을 추가하세요.

## 7. 평문으로 쓴 플레이 스타일을 옮기기

캐릭터별 운영 방식을 평문으로 적어 두면 이 양식으로 옮길 수 있습니다.
예시: [`ROUTE_AI_EXAMPLE.md`](ROUTE_AI_EXAMPLE.md)(평문) → [`ROUTE_AI_EXAMPLE.toml`](ROUTE_AI_EXAMPLE.toml)(설정).

| 평문 | 양식 |
|---|---|
| "체력 3000~5000일 때", "후반(~1500)" | `when`의 `my_hp_min` / `my_hp_max` |
| "+4FP 상황", "-3~-1FP 상황" | `fp_lead_min` / `fp_lead_max` |
| "이 상황에는 A, B, 수비 기술" | `[[situation]]`의 `prefer`(카드) + `weights = { card_defense = … }`(수비 전체) |
| "차지를 사용하지 않고 / 사용하며" | 패시브 능력 ID에 `[[effect]] use = true/false` |
| "겟 페이즈에 지금 쓸 카드를 가져옴" | `action`을 비워 둔 `[[situation]]`은 획득에도 적용됨 |
| "콤보 2 A → 3 B" | `[[combo]] cards = ["A", "B"]` (숫자는 콤보 순서이므로 빼고 적음) |
| "손패 부족/충분할 때 이 루트" | `[[combo]]`의 `when = { hand_max = 3 }` / `{ hand_min = 4 }` |
| "캐치는 ~일 때만" | `action = ["catch"]` 상황에 `prefer` / `weights = { play_catch_card = -15 }` |
| "브레이크 시 ○○ 보충" | `[[effect]] decision = "break_replenish"`, `pick = ["○○"]` |

평문을 쓸 때 아래를 적어 주면 옮길 때 추측이 줄어듭니다.

- **FP 기준**: "+4FP"가 상대보다 유리한 정도인지, 내 보유 FP인지
- **체력 기준**: 내 체력인지 상대 체력인지, 구간이 비지 않게(예: 3000~5000과 ~1500 사이)
- **빠진 상황**: 쓰지 않은 구간은 기본 AI를 따른다는 점
- **카드 이름**: 정확한 카드명(오타는 코드로 옮길 때 확인이 필요함)
- **조건이 엔진에 보이는지**: "파워풀 스윕이 브레이크되면"처럼 어떤 카드가 브레이크됐는지는 AI가 알 수 없어,
  "브레이크 보충 때마다"로 넓혀 옮깁니다

## 8. 기록 요령

- 한 AI 덱에 한 가지 운영 의도를 둡니다. 예: "니아 · 콤보 연습용", "루트 · 수비적".
- 루트·상황마다 `name`을 붙이고, 근거가 되는 공식 Q&A 번호나 실전 기록이 있으면 `#` 메모로 남깁니다.
- 값을 바꾼 뒤에는 그 AI와 몇 판 붙어 보고, 해석 결과 칸에서 의도대로 읽혔는지 확인합니다.
- 룰 해석이 불확실한 카드는 설정으로 억지로 맞추지 말고 `AUTOMATIC_EFFECT_RULE_QUESTIONS_KO.txt`에 질문으로 남깁니다.

### 빈 기록 양식

```toml
# AI 이름:
# 덱:            (덱 ID / 캐릭터)
# 의도:          (예: 상단 공격을 몰아치는 공격형 연습 상대)
# 마지막 점검:   (날짜, 몇 판, 결과)

style = "balanced"

[weights]

[prefer]

# [[situation]]
# name = ""
# when = {  }
# prefer = {  }

# [[combo]]
# name = ""
# cards = [  ]
# bonus = 3

[counter]
enabled = true
bonus = 2.0
scope = "hand"

[safety]
avoid_certain_loss = true
```
